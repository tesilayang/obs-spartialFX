# 风格组合预设：交互建议与动画候选总目录

研究日期：2026-11-13。用途：供用户挑选后续预设页改造与动画库范围。**本文列出 140 个候选：44 个运动、64 个转场/遮罩、32 个程序装饰。它们不是 140 个已实现功能，也不是首屏的 140 个按钮。**

本轮只研究并写清单，未修改 v3.6.0 插件、安装器、版本号或说明书，未发布 GitHub。现有八张模板卡片及图形基础可复用；新的随机组合器、各候选算法与新界面仍需确认后实施。

## 1. 建议的操作方式

### 1.1 默认：点风格、生成、应用

1. **选要动的素材**：直接显示当前时间轴已导入素材的小卡片，可多选、全选；锁定对象不可加入。第一次默认勾选未锁定素材。无需再次导入，也不要求逐个指定主体/背景等专业角色。
2. **点风格卡片**：温柔舒缓、简洁几何、活泼波普、纸片拼贴、科技界面、节奏快剪、朦胧梦幻、故障实验。卡片用短动画展示结果。风格单选起步；混合风格放详细控制。
3. **选运动和装饰**：运动用“轻／中／强”，装饰用“不要／少量／丰富”。额外提供“持续循环／单次展示”和直观时长；BPM、精确时间与空间坐标进入详细控制。
4. **点「生成一套」**：在临时预览中看完整组合；可点“换一套”，满意后点“应用”。取消恢复。重新生成不累加图层、图形和撤销记录。

默认保留当前构图和深度，不随机重排全部素材、不自动开舞台灯光。可标记一张“主体保持清楚”卡片；未指定时按所选素材整体范围留白，不声称自动识别人脸或人物。摄像机运动初始关闭，简单模式可用“让整个镜头也轻动”单独开启。

主体、背景、前景等内部角色可按用户指定和现有深度提供建议，生成后用缩略图说明“哪些素材会动”。无法从透明度和素材名称可靠推断语义，建议角色必须允许修正。

### 1.2 详细控制：手动拼零件

点击「详细控制」才展开以下六个可折叠组，默认模式保持短小：

| 组 | 手动选择内容 |
|---|---|
| 素材与构图 | 对象范围、主体保护区域、保持构图/重新排布、角色及深度 |
| 入场与退场 | 从动画库分别选择，可设无；方向、时长、依次错开 |
| 持续运动与镜头 | 图层动作、镜头动作、幅度、速度、循环及停留 |
| 遮罩与转场 | 指定接收素材、A/B素材、形状、方向、软边、中心及覆盖量 |
| 色块与装饰 | 从图形库多选；颜色、数量、位置、深度、锚定和循环 |
| 时间与随机 | 秒/BPM、拍长比例、相位、随机种子、锁定部分、有限区间烘焙 |

随机结果能在这里逐项查看和修改；手动选中的零件可锁定，随后仅重新随机未锁部分。支持“只换运动”“只换装饰”“只换配色”，这些入口放详细控制或生成按钮菜单，避免挤满新手首屏。

### 1.3 为什么这样调整

JIZURA 的实际代码把布局、入场、停留、退场、装饰、背景、镜头和转场分别注册，并使用标签、权重、种子与历史选择组织结果；规划器还保存中央留白和锁定规格。界面区分简单/详细、按现有设置重抽与整套随机。本方案借鉴这种分层操作，不要求用户理解内部注册表。

源码依据：[相机基础包](https://github.com/852wa/JIZURA/blob/4c8278cef161b38b132055e7b5efa112a5d41790/src/11p_bgcamB.js)、[新增镜头与转场](https://github.com/852wa/JIZURA/blob/4c8278cef161b38b132055e7b5efa112a5d41790/src/11p_x2_camtr.js)、[基础转场实现](https://github.com/852wa/JIZURA/blob/4c8278cef161b38b132055e7b5efa112a5d41790/src/11p_treattrans.js)、[装饰包](https://github.com/852wa/JIZURA/blob/4c8278cef161b38b132055e7b5efa112a5d41790/src/11p_decor.js)、[注册表](https://github.com/852wa/JIZURA/blob/4c8278cef161b38b132055e7b5efa112a5d41790/src/05b_registry.js)、[规划器](https://github.com/852wa/JIZURA/blob/4c8278cef161b38b132055e7b5efa112a5d41790/src/08_planner.js)、[界面](https://github.com/852wa/JIZURA/blob/4c8278cef161b38b132055e7b5efa112a5d41790/index.html)。这是结构和操作阅读，本轮未在本地运行 JIZURA。

## 3. 阅读清单的方法

- **L/M/H 为成本预估**：L=少量变换或简单覆盖率；M=多图形/噪声/额外合成；H=较多采样、碎片或多次绘制。均未移植性能实测，数量、分辨率、遮罩接收者数量会改变成本。
- **来源标签**：J=已读 JIZURA 固定提交；G=已核查 GL Transitions shader；F=FFmpeg xfade；C=Motion Canvas；R=Remotion 官方行为文档；E=依据基本图形/现有坐标体系独立提出的扩展。E 不代表在参考项目中找到同名成品。
- 每行是一个可辨认的动画方案，不把左右上下、镜像、反向或换色重复计为多个算法。入场多数可派生退场，反向播放不一定具有相同缓动，需要明确选择。
- 下面“镜头动作”须区分真正改变相机位姿/视野角与只改变图层缩放。JIZURA 多数相机接口返回二维平移、旋转、缩放；移植到本项目三维相机时必须按统一投影规则重新设计，不可直接照搬其数值。

## 7. 随机组合怎样保证能看

推荐“受规则约束的随机编排”，不能把库中所有动作等概率抽到同一画面。

### 7.1 分层决定

1. 读取用户所选风格、对象、轻重、装饰数量、时长和循环方式。
2. 按对象数量、锁定状态、现有动画冲突、是否需要A/B、是否允许重排筛掉不适用零件。
3. 选择一个主要运动，必要时增加一个低幅度背景/前景辅助运动；镜头动作最多一个，避免所有层和镜头同时大幅乱跑。
4. 从同一色板和图形家族选择零到两类装饰；入场/退场用兼容的遮罩家族。高级模式可主动提高数量。
5. 在限定参数范围抽方向、相位、幅度和顺序；先满足主体留白、画布边界、覆盖比例与绘制预算，再展示预览。
6. 保存完整生成结果、零件版本和seed。项目重启后读取结果，不重新抽签；定位同一时间必须得到同样画面。

循环动作要校验首尾位置与速度，非循环动作明确入场—停留—退场的阶段。颜色、几何边缘和A/B交换使用同一时间输入，避免“色块盖住了但内容提前跳了”。

“随机增加遮罩色块”需要拆成用户能理解的开关：**装饰色块（看得见）／图层露出遮罩（切形状）／A-B过场（换素材）**。三者可以共用几何算法，但用途不可混淆。D类常驻装饰不会因为勾了“丰富”就悄悄变成裁切蒙版。

### 7.3 与当前工程衔接

- 继续使用 `evaluateSceneAt()` 和统一空间坐标；不在随机模块另造一套深度/位姿规则。
- “脚本库”面向用户是动画零件库；推荐保存为有版本的动作定义与受验证参数，由原生函数执行。不为简单随机功能引入任意JS解释器或浏览器来源。
- 随机与手动共享同一生成结果。有限动作可写现有关键帧；周期动作可用现有MotionBlock；不能为了数量把所有动作强塞成正弦波，弹簧、阶梯、路径、时序遮罩需要各自求值器。
- 转场几何需要独立的进度/时序模型，受光FX保持独立。需要A/B纹理或UV重采样的候选单独接入，不能用色块覆盖冒充翻页、流体或碎片。
- 预览保持临时文档；应用一次事务；撤销恢复一次生成。处理动画冲突时简明提示冲突对象，默认不覆盖已有用户轨。
- 按实际接收者和副本计算预算；保持现有32来源、128图形、512循环块上限，复杂效果需更小的单效果预算。
