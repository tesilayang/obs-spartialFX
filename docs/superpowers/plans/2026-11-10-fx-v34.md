# OBS Spatial FX v3.4 Implementation Plan

用户已确认目录和交互并授权正式开发。原选择文件保留；3 个待定项以本次确认覆盖为需要。暗角圆度 0=矩形，1=跟随画布的椭圆。旧说明书不更新。

## 交付与架构

每个 Layer 增加独立 FX 配置，以 instanceId 关联，不以名称或 UI 行号关联。新场景为空；加号仅列当前舞台时间轴图层。素材卡片提供 13 个带悬停说明的图标；未启用组和子项不渲染、不分配处理表面。大组图标控制启用和展开，复选框控制子项和参数区。参数使用现有 NumericSlider，0.01 步进，紧凑排列。移除卡片恢复该实例的原始画面。

渲染采用每个子效果按需专门化编译、每图层两个复用表面的效果链；历史效果额外按需双缓冲。UI 发布不可变快照，渲染线程不等待 UI。引用源仅允许同舞台已导入实例；本地 LUT/纹理由 UI 载入 CPU，GPU 上传仅发生于渲染上下文且在资源变动时进行。失败显示日志并保留原画面。

FX11 几何运动进入统一场景求值器，灯光绑定继续使用相同世界坐标。既有灯光与新增材质/阴影互通。安装器沿用 ProgramData 系统插件路径、OBS32/33 双加载布局和运行进程保护。

## 执行任务

1. 配置和目录：新增 fx_catalog.hpp/.cpp 与分组定义，92 子项、113 原选择完整覆盖；单元测试验证默认空、组/子项开关、独立实例、序列化、非法值清洗。
2. 效果实现：分组着色器正文与参数定义分文件；统一 common/footer，由 fx_renderer 组合编译。包括模式差异、透明边界、外部引用、LUT、历史与运动信息。为每种效果保留精确说明。
3. UI：新增 fx_panel.hpp/.cpp，素材卡片、加号菜单、13 图标入口、按需子项和参数、颜色/模式/资源选择；接入 Dock 的 commit、load、import/remove 同步。
4. 渲染与保存：接入 Stage、统一场景求值、model schema5；旧版几何和灯光行为回归。关闭处理时跳过新通道，复用资源无每帧创建。
5. 实测：VS2022 构建、CTest、真实 OBS32/33 UI/保存重启、逐效果 GPU 编译与截图差异、1080p60 稳定性、升级运行保护/卸载注册检查。未执行项明确 NOT RUN。
6. 交付：3.4.0 版本、完整安装包、源码/符号/验证证据及开发记录；安装包覆盖升级 v3.3，保留原配置。不得将未完成效果标记可用。

## 集成修正记录

真实 D3D11 测试发现 OBS effect parser 不保留全局 const 初始化，因此改为编译前把函数体中的效果选择符直接替换为整数字面量。历史效果第二通道重新绑定 image、strength、effect_result，因为 gs_technique_end 会清空参数。材质映射使用裁切中心、实际世界基向量及求值后的摄像机位置；运动模糊使用投影基向量的雅可比逆换算 UV，隐藏/缺失图层打断运动历史。
