# OBS Spatial FX v3.4.1 implementation plan

**Goal:** Add independently selectable SMAA 1x, FXAA and low-cost RCAS under quality correction, preserving all v3.4 settings and installer upgrade behavior.

**Authorized decisions:** Native AA is deferred and hidden per the user's November 11 reply. Existing manuals must not be updated. Execute inline in this session; do not repeat approval or delegate. No Git repository exists, so baseline snapshots replace commits.

**Architecture:** Retain all existing stable IDs and append FX02.2 (SMAA), FX02.3 (FXAA), FX02.4 (RCAS). Use a dedicated three-pass SMAA renderer and shared immutable Area/Search LUTs, created lazily in graphics context. FXAA and RCAS use individual one-pass specializations. Two collapsible subpanels under group 2 keep these separate from legacy sharpening. SMAA and FXAA are mutually exclusive, RCAS may follow either. Disabled effects execute no passes and own no dedicated GPU resources.

**Tech:** VS2022 C++17 /utf-8, Qt6, OBS 32/33 D3D11, current embedded installer. System installation stays in ProgramData. Never overwrite running OBS.

## Resource choice and limits

RCAS is chosen for a fixed five-texture-tap, single-pass implementation with no upscale or temporal buffers. Default CAS also compiles to five taps; CAS with better diagonals uses nine. RCAS is selected for its robust clipping limiter and noise protection, not a claim that it universally beats default CAS. Actual timing must decide budget; no integrated-GPU performance measurement is available. Neither spatial AA reconstructs detail missing from source video or removes jaggies introduced after the layer FX pass by later stage perspective transforms. Native AA requires a future temporal rendering design with per-pixel motion/depth/jitter data and its own performance evaluation.
