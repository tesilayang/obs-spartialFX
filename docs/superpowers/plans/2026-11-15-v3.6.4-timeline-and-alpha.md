# v3.6.4 透明边缘与统一时间轴实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 修复透明来源白边和预设动作不可直接编辑的问题，将图层、灯光及 FX 参数纳入同一套可编辑时间轴。

**Architecture:** 复用现有参数轨、曲线、撤销和 `evaluateSceneAt()`。以稳定对象标识和按对象类型注册的参数描述连接页面、时间轴及渲染；预设运动生成普通关键帧。透明边缘先分段复现，再修复证据指向的 Alpha 或采样环节。

**Tech Stack:** C++17、VS2022/MSVC、Qt6、OBS 33.0.1、现有图形着色器和 CMake/Ninja。

**Spec:** 本文“确认范围”及仓库 `DEVELOPMENT_STANDARDS.md`、`docs/architecture/SPATIAL_COORDINATE_CONTRACT.md`。

**状态：用户已确认，已完成核心研发和最终安装载荷专项验收。** 真实 NDI 因无发送端 BLOCKED；自动加载迁移没有可见取消入口。详见 `docs/v3.6.4/TEST_REPORT.md`。

## 全局约束

- 版本定为 3.6.4；兼容性验收只运行 OBS 33.0.1。
- 使用说明书仅在用户明确要求时更新；本版更新开发记录和专项测试报告。
- 保留现有时间轴默认 6 秒视窗、连续参数 0.01 步进、位置与旋转数值映射。
- 所有空间计算复用 `evaluateSceneAt()`，播放和定位禁止回写基础布局。
- 关联对象使用稳定 ID，FX 参数使用目录中的字符串键，禁止以列表索引持久化关联。
- 渲染消费不可变快照，禁止等待 UI、逐帧加载文件或逐帧创建着色器与纹理。
- 只验证本次变更及直接受影响的调用方；公共动画模型变更需要覆盖新增数据的保存、重启和工程往返。
- 保留工作区已有说明书重命名及展示版文件。本计划不授权 Git 提交、推送或发布 Release。

## 一、确认范围与可见操作

### 1. Spout2 / NDI 白边

目标是同一透明来源直接显示和导入 Spatial FX 后，在关闭灯光与 FX 的基线下保持相同边缘。缩放、旋转及点亮灯光后，透明边缘也应正确参与合成。

截图显示关灯后仍有浅色边缘，因此分开检查来源纹理、透明度预乘、缩放采样、FX 和轮廓光。当前根因尚未确认，不把收缩 Alpha、硬切透明度或关掉轮廓光当作通用修复。

### 2. 预设运动变成普通关键帧

- 新预设的运动直接生成普通参数关键帧；对象摘要行显示关键帧标记，展开可编辑各参数。
- 支持框选、移动、删除、复制、粘贴、缓动、曲线、撤销和复位。
- “应用到时间轴”和“补充至时间轴”使用同一生成规则。
- 预设循环在用户指定的持续时间内生成关键帧；时间轴的循环播放负责重复播放这一段，不生成无限数据。
- 预设绘制的装饰图形继续使用现有图形生成器，其位置、旋转、缩放等运动进入普通轨道。程序化绘制本身保留，删除图形对象可以移除装饰。
- 旧循环运动块迁移成关键帧，转换前保留原始备份；迁移失败保留原数据并报明原因。
- 清理遗留预设时长引用，删除动作后不能仍被无内容的预设记录延长播放终点。

### 3. 图层右键菜单

| 菜单 | 默认行为 |
|---|---|
| 复制时间轴信息 | 复制当前对象的全部动画；已明确选择参数轨时只复制所选参数轨。包含时间、值、缓动和曲线手柄。 |
| 粘贴时间轴信息 | 将复制内容的最早关键帧对齐当前播放头，保留内部时间间隔。仅写入兼容参数。 |
| 删除这个图层 | 二次确认后移除 Spatial FX 内的对象及其子轨，保留 OBS 原始来源。 |
| 复制这个图层 | 复制实例的基础布局、FX 和动画到插件剪贴板。 |
| 粘贴图层 | 创建具有新实例 ID 的独立实例，引用原 OBS 来源，动作和 FX 可独立编辑。 |

- 粘贴冲突先显示受影响参数与时间段，确认后替换这些参数在该时间段内的关键帧；区间外数据保留。
- 类型不兼容的参数列出跳过原因；全部不兼容时不修改数据。
- 锁定对象及锁定参数轨禁止写入；每次粘贴、删除作为一次撤销操作。
- 灯光与 FX 行使用对应对象菜单：时间轴信息可复制粘贴，删除需确认；摄像机和整体输出不提供删除对象。
- 复制图层不重复打开摄像头、Spout 或 NDI 连接。

### 4. 灯光进入时间轴

- 已创建灯光显示为独立对象，点光源和面光源共用现有灯光模型。
- 数值轨覆盖：XYZ、强度、范围、环境补光、阴影强度、接收面深度、尺寸、衰减、软阴影半径、轮廓光强度、轮廓光宽度、轮廓光柔和度。
- 灯光颜色和阴影颜色支持关键帧；颜色控件继续使用整条底色预览、十六进制色值和实时预览。
- 启用、可见、投影开关、灯光类型、绑定对象及接收对象仍由灯光页控制，本版不新增这些非数值项的动画。
- 灯光页与时间轴共用参数编辑逻辑；定位后显示当前求值，是否写入关键帧遵守现有自动关键帧开关。基础布局编辑仍写基础值。
- 绑定图层时先计算灯光自身的局部动画，再跟随图层的最终位姿，避免重复位移。
- 删除、重排或主灯提升时，已有关键帧继续跟随原灯光 ID。

### 5. FX 子功能进入时间轴

- 激活 FX 子功能后，在所属素材下显示一条 FX 子轨；不额外增加可见素材、不改变素材深度。
- 强度、目录内全部数值参数及效果颜色可以打关键帧；范围与 FX 页一致。
- 模式选择使用保持插值，整数计数按整数求值，禁止插出不存在的模式。
- 图片、LUT 路径、辅助素材选择等资源引用保持静态。
- 关闭 FX 后保留动画，轨道变灰并停止该效果处理；再次启用恢复原动画。
- FX 页和时间轴共享自动关键帧、锁定、撤销和定位规则。
- 几何、舞台、历史帧类 FX 也接入统一时间，跳转或倒放时重置受影响的历史缓存。

默认仅展开对象摘要，参数按需展开；结构示例：

```text
摄像机
图层 · 角色
  位置 / 旋转 / 缩放 / 透明度
  FX · 辉光
    强度 / 半径 / 阈值 / 颜色
灯光 · 点光源 1
  位置 / 强度 / 范围 / 软阴影 …
```

## 二、已确认的代码事实

1. `src/presets/composer.cpp` 在循环模式生成 `MotionBlock`；非循环路径才写入普通曲线。
2. `src/editor_timeline.cpp` 单独绘制运动块色条，关键帧选择不包含运动块。
3. `src/editor.cpp` 的删除和复位只清普通动画，`scene_evaluator.cpp` 仍继续叠加运动块。由此解释“色块不能通过删除关键帧或复位去掉”的结构性原因。
4. `Light` 没有独立实例 ID 和动画字段；`FxInstance` 没有动画字段。当前时间轴只认识摄像机、整体输出、图层与装饰图形。
5. `src/stage.cpp` 将来源绘制到缓存纹理，`data/effects/spatial.effect` 在最终合成中处理预乘 Alpha。直通与中间纹理路径的差异需要通过真实来源和像素数据进一步定位。
