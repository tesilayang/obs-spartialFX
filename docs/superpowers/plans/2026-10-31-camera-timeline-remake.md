# OBS Spatial FX 摄像机与多图层时间轴重制计划

> 后续执行建议使用 superpowers:executing-plans，按下面的任务逐项实现、编译和验收。本轮仅编制计划；不启动功能开发，不分配新版本号，不改动已交付 v3.1 安装包。

**目标：** 将摄像机页重制为面向非剪辑专业用户的“对象时间轴 + 参数编辑器 + 曲线编辑器 + 音频节拍预打点”，相机与图层均能独立动画。

**架构：** 原生 Qt6 Dock；统一参数注册表、按参数存储的动画曲线、单一场景求值器、独立的时间轴视口及后台节拍分析。保留 UI 单写入和不可变渲染快照，不让渲染线程等待 UI/音频分析。

**技术栈：** C++17、VS2022 x64、Qt6 Widgets、OBS32+ 公共 API、现有 CMake/Ninja 构建；音频离线解码优先验证 Windows Media Foundation，节拍检测在本地后台执行。

**设计依据：** 用户本轮五项需求、已确认“按拍长比例”的预打点规则、本文件第 1～8 节，以及 `docs/architecture/SPATIAL_COORDINATE_CONTRACT.md`。

**状态：** 2026-10-31 计划草案，等待用户审阅。所有新功能、新模型及性能指标均未实现、未测试，不记为 PASS。

## 1. 范围与方案选择

重制的是整个摄像机工作流，而非继续往旧表单追加按钮。

| 方案 | 内容 | 判断 |
|---|---|---|
| 推荐：Qt6 时间轴 + 按参数动画轨道 | 上方选对象和时间，下方编辑参数/曲线；和现有插件直接共用数据 | 覆盖全部需求，改动范围可控 |
| 只调整旧表单布局 | 保留整组关键帧与固定总时长 | 无法实现可靠的参数曲线、长时间轴与节拍打点，不采用 |
| 嵌入完整视频编辑器/浏览器编辑框架 | 引入另一套 UI、工程及播放系统 | 依赖和线程复杂度过高，本轮不采用 |

这次分成基础模型、时间轴交互、参数与曲线、音频节拍四个可独立验收的模块。功能仍在 OBS 内；原生 Dock 可以像 OBS 其他面板一样浮动/放大，不建立独立常驻程序。

不扩展为剪辑软件：本轮不做素材裁切拼接、多机位切换、音频混音器、视频导出和第三方工程导入。灯光/FX 页面暂不全面改版，但其坐标计算需要接入共同求值器并做兼容回归。

## 4. 选择、参数与关键帧规则

### 4.1 对象选择

- 相机、全画面合成、每个已导入图层各有对象轨道；图层可展开位置/旋转/缩放/透明度/环绕子轨。
- 单击对象名或空白轨道选中待编辑对象；不自动改变播放头。单击关键帧则选中对象/参数并定位该时间。
- 时间轴、空间图层列表、结构图、下方编辑器保持同一对象身份，不能使用行号作为长期身份。
- 单个活动对象用于显示属性，关键帧支持 Shift/Ctrl 多选、框选、拖动改时间、复制/粘贴和 Delete 删除。
- 对象行的汇总菱形拖动，只移动该对象此时刻全部子关键帧，不牵连其他对象；实际涉及哪些参数在拖动时高亮。
- 轨道锁定禁止编辑与批量写入；它与素材是否可见、是否参与渲染分别控制。

### 4.2 参数内容及命名

| 对象 | 可动画参数 | 命名/数值原则 |
|---|---|---|
| 相机 | XYZ、俯仰/偏航/滚转、垂直FOV、目标XYZ、环绕半径/水平角/俯仰角 | 用“推近/拉远”“看向目标”说明真实作用；派生值不能伪装成可编辑值 |
| 图层 | XYZ、旋转XYZ、缩放XY及等比锁、透明度、环绕目标/半径/水平角/俯仰角 | 初始值与空间图层页一一对应；等比锁是编辑辅助，不在加载时改变旧缩放 |
| 全画面合成 | 输出缩放XY、透明度 | 明确为合成后的全画面效果，不把它叫相机透明度或相机物理缩放 |

图层/相机的参数行使用同一控件结构：动画开关、名称、数值滑条、数值框、上一帧、菱形、下一帧。XYZ 沿用 v3.1 的固定滑条映射；连续参数精度为 0.01，时间字段单独按时间精度处理。环绕角允许多圈，数值框不能被 ±180° 限制。

建议缩放显示百分比、透明度显示百分比，两页同步采用相同显示单位；内部仍保存倍率和 0～1。迁移时不能把旧 sx=1.25 当作 1.25%。

### 4.3 基础状态与动画状态

- 没有启用动画的参数，调节即编辑基础状态；单独显示“基础值”。
- 启用动画后，调节在当前时间更新/生成该参数关键帧；行内菱形和状态栏明确提示“已记录 @ …秒”。
- 第一次在 t>0 启用参数动画时，同时在 0 秒保存此前基础值，避免第一帧把此前所有时间回填成终点值；这两个键作为一次撤销事务。
- 顶部“记录关键帧”对当前选中的参数记录；没有选择参数子轨时，对当前对象的常用运动参数组记录。菜单明确列出将记录的位置/旋转/缩放/透明度，避免误给所有对象打帧。
- 每行菱形只影响该参数。编辑器下方可直接输入选中关键帧的时间和数值，输入 120.5 秒即可跳到该帧，不受当前视口和动画尾点限制。
- 暂停仅冻结当前时间，不恢复初始值；回到开头仅移动播放头。两者都不删除关键帧或覆盖基础状态。
- 切到“编辑基础布局”后暂停动画预览；两页同时显示基础状态。恢复预览后重新求值，不累积变换。
- 多选关键帧改时间按统一增量移动；落到已有关键帧时默认不覆盖，显示冲突并允许改落点；明确的“替换”操作才可覆盖，且可撤销。

### 4.4 缓动与贝塞尔

快捷项：线性、缓入、缓出、缓入缓出、保持、自定义贝塞尔。UI 使用“进入此帧慢下来”“离开此帧慢起步”解释方向，避免把两者混淆。

曲线页显示当前参数的时间—数值曲线，可拖关键帧和入/出手柄；数值/时间编辑与主时间轴双向同步。贝塞尔先实现时域/数值曲线，不能把缓动菜单冒充可编辑曲线。时间手柄保持单调；透明度、FOV 等有范围的参数在最终求值时受合法范围约束，并显示超限提示。

空间环绕由明确的轨道约束实现；任意三维空间路径的额外切线编辑不作为本轮验收前提。旋转曲线提供最短路径/保留圈数，避免 0→360 被消除。旧 Smooth/CubicInOut 保留精确的兼容求值，不能用观感接近的贝塞尔强行替换。

## 5. 必须有的按钮与复位确认

| 按钮 | 具体行为 |
|---|---|
| 记录关键帧 | 在播放头为当前参数或当前对象参数组写入一次关键帧，可撤销 |
| 删除关键帧 | 删除已选关键帧；未选中时删除当前对象/参数在播放头精确时间的帧；无帧时明确提示 |
| 播放预览 | 从当前播放头播放；已经到结尾时回到 0；没有时间跨度时提示先建立两个时间点 |
| 暂停预览 | 保留暂停的画面和时间，恢复播放从这里继续 |
| 复位当前图层 | 必须先显示原生确认对话框，再移除该层运动曲线并恢复导入默认的位置/旋转/缩放/透明度 |
| 复位所有图层 | 必须先显示原生确认对话框，列出受影响图层数/关键帧数后执行；默认尊重锁定 |
| 撤销/重做 | 单个拖动、批量移帧、复位和节拍生成均是一项编辑事务 |

“复位当前图层”示例文案：“将复位‘人物’的运动、缩放与透明度，并删除 12 个运动关键帧。素材及灯光绑定会保留。是否继续？”按钮为“取消”和“确认复位”，取消为默认焦点。

“复位所有图层”列出可复位 M 层、锁定 N 层将保留；可显式勾选包含锁定图层。该按钮默认不复位相机。相机和全画面合成选中时，当前图层复位按钮禁用；各自的“恢复默认镜头/合成”独立提供同样的确认。

复位不删除 OBS 源、不解除精确身份、不改变素材名称、图层深度顺序和受光/阴影开关；恢复的是动画工作流管理的状态。旧工程没有完整导入默认值时，迁移一次捕获可恢复基线并记录来源。

## 6. 时间轴视口与动画时长

严格分开四件事：可见范围、播放头、动画内容终点、可选循环工作区。

- 首次打开默认可见范围 0～6 秒。放大、缩小、平移只改变显示，不移动或拉伸关键帧。
- Ctrl+滚轮以鼠标所在时间为锚点缩放；Shift+滚轮/中键拖动横向平移，普通滚轮上下滚轨道。提供可发现的 +/−、底部平移条、“显示全部”“回到播放头”。
- 左侧对象名固定，不随时间缩放横移；时间刻度按缩放程度自动选择秒/分钟/小时，播放头数值一直可直接输入。
- 动画终点 T_end=所有保留的相机、图层及全画面有效关键帧的最大时间。停用/锁定的已存关键帧仍保留在内容范围内，避免重新启用时尾点消失。
- 无关键帧时内容终点是 0，但视口仍显示 6 秒；在很远处移动播放头或仅有节拍参考标记不会延长动画，真正写入关键帧才延长。
- 删除最晚帧重新计算终点；若播放头超出新终点，暂停在保留的预览位置并显示“超出动画范围”，下次播放按新范围运行，不静默改写键时间。
- 用户可在尾点外直接录帧，不先设置“总时长”。原“持续时间”改为只读的“动画长度”，可选工作区仅限制循环播放，不截断内容。
- 不设 3600 秒/24 小时的业务上限；存储/比较/滚动均以 TimeUs 运行。长整型及资源容量仍有实际边界，不能承诺数学上的无限；遇到容量压力必须提前提示、可取消，不静默截断。
- 移除 256 帧硬限；动态曲线按时间排序，求值采用二分查找，绘制只遍历可见关键帧。长时间不生成与总秒数成比例的超宽 QWidget，也不把微秒直接塞进 32 位滚动条。
- 初始时间显示毫秒，支持直接输入更高精度；帧吸附按 OBS 实际帧率。BPM 候选保留子帧精度，可选择吸附到帧并在合并前显示重复数。

## 7. 最下方：已有 OBS 媒体的节拍预打点

### 7.1 媒体选择与分析

来源下拉从当前 OBS 场景中的媒体源枚举，按 source UUID 关联，并标注所属场景、源类型、文件可用性及音频分析能力。相同源重复引用不重复解码；同名不同源不混淆。用户不必重新浏览磁盘选文件。

第一阶段完整离线分析优先支持 OBS 本地媒体源；在工作线程读取其文件并独立解码 PCM，不重启、不定位、不静音用户正在使用的源，也不创建会出声的第二个 OBS 源。

解码首选验证 Windows Media Foundation Source Reader，依赖系统组件，不私自链接 OBS 打包的私有 FFmpeg DLL；不能因为 OBS 能播放就断言系统离线解码器也支持。Task 1 必须实际验证 WAV/MP3/MP4(AAC) 及无音轨文件、错误文件；FLAC/MKV 等逐项登记能力。若系统解码失败，显示具体原因，允许手填 BPM 和首拍偏移，或显式开始实时采集分析；不能把格式失败装作识别成功。

VLC 播放列表、网络流和无限时长来源在列表中说明能力边界。没有可读取本地文件的来源，使用 OBS 公共音频捕获回调收集用户指定的时间窗口，再后台分析；只能生成已观察区间的候选点，不能承诺预知未来可变节拍。实时来源未提供有效PCM、未播放、源失效时明确显示“无可分析音频”。OBS的静音标记和没有音频数据分别处理；本地离线分析不受该素材是否静音影响。

### 7.2 BPM 与真实节拍点

分析过程：分块 PCM → 每声道能量/频谱通量 → 起音强度包络 → 周期估计 → 节拍序列跟踪 → BPM、置信度和各拍时间。不能只算 BPM 再从文件 0 秒机械均分；歌曲前导静音、首拍偏移和速度变化都需要处理。

显示自动 BPM、节拍置信度、首次有效拍点，支持手工 BPM、×½/×2、点按测速和首拍偏移。低置信度/无稳定节拍时不默认生成；允许改为人工节拍网格。鼓点密集、切分拍、环境音不保证唯一正确 BPM，手动校正必须可用。

支持分析进度、取消及结果缓存。大文件分块解码，不整首展开多声道 PCM 常驻内存；完成/取消后释放解码器和音频回调。缓存放插件配置的 cache 子目录，临时 PCM 不写进 OBS 场景 JSON。缓存键包含源UUID、文件标识/大小/修改时间、音轨及分析算法版本；失效后提示重新分析。

### 7.3 已确认的比例规则

用户已确认按拍长比例。选项：1/4 拍、1/2 拍、1 拍、2 拍、4 拍及自定义正比例；附加最小秒数默认 0，仅在需要时限制密度。

稳定 BPM 的拍长 B=60/BPM：

    目标最小间隔 = max(拍长比例 * B, 附加最小秒数)

例：120 BPM，B=0.5 秒。1/4 拍为 0.125 秒；1/2 拍为 0.25 秒；1 拍为 0.5 秒；2 拍为 1 秒。先从检测到的拍序列生成/细分，再按最小间隔筛选；比例小于 1 的细分点是插值网格，界面不能标成已经检测到真实鼓击。非整数比例在该拍坐标上均匀采样并标明来源；变速音乐使用相邻已检测拍点间的局部拍长，不把全曲锁成一个周期。

增加范围选择、首拍对齐、时间轴偏移和目标参数选择。素材原始文件时间与时间轴通过明确的偏移/裁切起点/播放速度映射；默认以素材第一有效拍加用户偏移开始。若读取到 OBS 非 100% 播放速度，先显示映射状态，未经验证的速度语义不能静默套用。

### 7.4 预打点与真正运动分开

1. 点击分析，显示波形缩略图、拍点及候选 BPM。
2. 设置比例与范围，点击“预览候选点”，只生成参考线/浅色菱形，显示预计数量。
3. 选择相机或图层及具体参数。按“写入选中参数轨道”才变成真正关键帧；不自动对全部图层打帧。
4. 默认在对应时刻采样当前曲线值；无曲线时取基础值。这个模式是“预打点”，不会凭空产生运动；已有贝塞尔曲线拆段时用精确拆分保留原轨迹。
5. 可另选明确命名的“按节拍生成运动”模板，再设置起止值/振幅，才生成交替推拉或摆动。模板作为增强项，不能替代手工关键帧，也不能默认启用。
6. 已有同时间关键帧默认保留并报告跳过数量；锁定轨道跳过。明确选择替换才覆盖；一键撤销整个批次，不逐帧撤销几千次。

只有节拍参考轨不延长动画；烘焙后的最晚关键帧自动延长动画。生成前显示预估帧数和内存/配置影响，超大批次分块可取消。取消时整个事务回滚。

### 7.5 音频与动画预览

节拍分析默认不控制原媒体播放。提供单独的“联动所选媒体预览”选项，明确说明会改变该素材播放位置；用户启用后才通过其支持的媒体播放/定位 API 联动。

独立预览使用插件单一播放时钟；联动模式以媒体报告的有效时间作为主时钟，并处理等待、暂停、循环、seek 和源消失。不能让 UI 定时器、OBS 渲染时钟和音频各自推进后产生持续漂移。OBS 媒体 API 通常是毫秒精度，源类型与非1倍速映射必须实测，不可宣称采样级同步。

建议 schema 从 3 升至 4，产品版本号在实际发布时另定。

| 模块 | 最少数据 |
|---|---|
| 对象 | 稳定 ObjectId、类型、名称引用、BaseState、ImportDefaults |
| 参数 | ParameterId、单位、范围、默认值、读写规则、可动画能力 |

| 关键帧 | 稳定 KeyId、TimeUs、值、入/出插值与手柄、旋转策略 |

用命令/事务统一所有入口：插帧、改值、拖动、复位、节拍生成都经过同一个 EditorController 和 undo stack，再发布不可变动画快照。播放头推进及选择/缩放不产生编辑命令，也不逐帧序列化全部配置。

持久化继续使用 source private settings 的 spatial_fx_model 和 owned-payload set/get API，禁止回退到共享 public settings 的 obs_source_update。拖动时合并预览更新，结束后生成一次可撤销记录和延迟保存；只读播放时间/选区视口与重型曲线变更分开发布，避免每次拖播放头深拷贝所有曲线。

迁移旧整组帧为每参数通道；保留原时间、数值、每段 easing 和旋转最短路径。旧显式 animationDuration 可能导致最后一帧后的保持或尾点外关键帧不播放：必须保留原帧，显示旧播放范围作为可选工作区；默认工作区匹配旧预览、内容终点仍按最长帧计算。迁移报告写明“旧结束时间/新内容终点”，不能通过删除尾点外帧来兼容。

新工程初始视口为 6 秒；迁移旧工程也不能把原最长帧压到 6 秒。首次保存前保留 schema3 原始载荷备份；v3.1 不能直接编辑 schema4，降级恢复备份，而非假装双向兼容。用户命名预设、同源不同sceneitem、已失效锚点均需迁移测试。
