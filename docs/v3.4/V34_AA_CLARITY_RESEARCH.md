# 抗锯齿与低开销清晰化方案调研（待决定）

日期：2026-11-11。此文件是本次研发补充报告，不改动已有说明书。本次 v3.4 补丁**没有加入**以下新算法。

## 先说明用途

抗锯齿是把斜线边缘的“台阶”变平顺；锐化是增强已有边缘的对比，让画面显得清楚。它们是两件事。单纯锐化有时会让台阶更明显，不能把锐化按钮称作抗锯齿。

SMAA 通常在 **GPU** 执行，并不是主要靠少量 CPU 的处理。FXAA、CAS、RCAS 同样适合 GPU。这里的“低开销”是算法结构和官方定位的比较，**不是本插件实测耗时或零资源承诺**。

| 方案 | 用浅显的话说 | 典型处理结构 | 主要优点 | 代价和限制 | 建议 |
|---|---|---|---|---|---|
| FXAA | 找到画面中明显的锯齿边，再将附近像素轻轻混合 | 单道图像后处理，可设置质量档 | 接入较轻，适合先试用的省资源抗锯齿 | 细字、发丝、纹理可能变软；不恢复丢失细节，不解决所有运动闪烁 | 第一优先：独立“抗锯齿”子功能 |
| SMAA 1× | 识别边缘形状，再按边缘形状计算混合 | 边缘检测、混合权重、邻域混合三道处理；使用两张查找纹理和中间纹理 | 更有针对性地处理边缘，是质量优先候选 | 工程与纹理成本高于单道方案；1× 不包含时间累积；仍需本机画质和耗时对照 | 后续可选“质量优先”档，不作为“几乎免费”的方案 |
| AMD CAS | 根据周围画面的对比，决定哪里需要锐化、哪里少锐化 | 自适应锐化；官方也支持可选放大 | 比简单一刀切锐化更适合做轻量清晰化候选 | **不是抗锯齿**；过强仍可能强调噪点和锯齿；不能生成真实丢失细节 | 第一优先：独立“自适应清晰化”子功能，与 FXAA 分开 |
| AMD RCAS | 在锐化时限制过冲，并减少对疑似噪点的强化 | FSR1 中独立的一道锐化，十字形五点采样；不负责缩放 | 适合评估缩放之后的轻量锐化 | **不是抗锯齿**；与 CAS 的用途重叠，不能仅因名称不同重复堆按钮 | 与 CAS 做对照后择一，暂不双重加入 |
| 现有锐化的优化 | 让当前锐化更克制，少出白边，少放大噪点 | 利用现有邻域采样与混合强度 | 工程变化最小，操作最少 | 与现有功能重叠，不是新抗锯齿算法 | 可作为独立修复评估，避免包装成多个重复效果 |

“第一优先”是针对本工程的研发建议，尚未在本插件接入并进行性能测试。它不是对所有画面都最好的画质排名。

## 如果决定增加，建议的操作方式

放在现有“锐化”相关入口中，但明确分成“抗锯齿”和“清晰化”两个可独立开关的子功能，均默认关闭。

1. 抗锯齿先试 FXAA，提供强度/质量档及原画对比。
2. 清晰化试 CAS；RCAS 作为对照候选，选择较合适的一种，避免重复选项。
3. SMAA 1× 在确实需要更好边缘效果时再增加。不要把 T2×/4× 的时间累积方案一起塞进首版。
4. 通常先抗锯齿，再少量清晰化；必须实测两者叠加是否重新放大锯齿。

这里有一个位置上的区别：给素材本身抗锯齿，不能自动消除素材经过透视旋转后在舞台上新产生的轮廓锯齿。后续研发需对照“图层内部处理”和“舞台合成后处理”，再决定是否提供舞台级抗锯齿。不能只增加图层按钮就保证舞台所有边缘变平顺。

透明素材还需保留 Alpha、正确处理预乘颜色，防止黑边和彩边；测试中须覆盖半透明边缘、细字、人物头发及旋转图层。这些是接入时的验证要求，不是已经完成的新功能。

## 决定前应了解的范围

- 本次没有新增 AA Shader，也没有改动锐化算法；保持 v3.4.0。
- 新算法的 1080p/60 和 4K 耗时、显存增量、AMD/NVIDIA 实机对比：**NOT RUN**，因为尚未接入。
- 不用十多年前白皮书的显卡数据当作本机性能保证；也不把 GPU 耗时算成 CPU 耗时。
- 如同意追加一个小版本，建议先做 FXAA + CAS 两个独立选项，并以真实边缘和细字样张及显卡计时作为验收依据。具体版本号由你确定。
